# 《女巫的毒药：薯条篇》网页版原型设计

日期：2026-07-19

## 1. 目标

交付一个可在本机浏览器中验收的竖屏双人网页原型。两个浏览器标签分别模拟两台手机，玩家可以通过快速匹配或邀请房间进入同一局游戏，秘密调制一根整蛊薯条，再轮流选择并虚拟吃掉桌面上的薯条。

本原型要验证四件事：

1. “藏毒—试探—揭晓”的基础心理战是否清晰。
2. 赛前自定义酱料是否能产生足够强的归属感和节目效果。
3. 在线匹配和好友邀请是否能在极少步骤内开局。
4. 表情特写是否能成为值得录屏传播的回合高潮。

## 2. 不在本次范围内

- 不接入真实抖音账号、好友面板、广告、支付或审核后台。
- 不部署公网服务，不承诺跨网络设备访问。
- 不制作角色养成、排行榜、商城、任务系统或复杂卡牌系统。
- 不使用真实人脸识别、摄像头或真人表情生成。
- 不鼓励玩家在线下复刻极辣、芥末、混合刺激物或强迫进食挑战。

## 3. 方案比较与选择

### 方案 A：服务端权威的双标签在线原型（采用）

客户端只提交“排队、进房、调制、选薯条、重赛”等意图，房间状态、隐藏配方、当前回合和胜负全部由本地 Node 服务端判定。优点是最接近未来抖音双设备版本，能真实验证秘密信息、匹配和掉线处理；代价是需要启动本地服务。

### 方案 B：单设备轮流传递

两人共用一台设备，通过遮挡页轮流操作。开发更简单，但无法验证在线匹配、好友邀请和服务端防偷看，也不符合当前产品方向，因此不采用。

### 方案 C：纯前端双角色模拟

一个页面同时展示双方状态，依靠前端脚本模拟对手。演示方便，但隐藏信息可以被客户端读取，无法作为联机架构依据，因此不采用。

## 4. 核心规则

### 4.1 开局

- 每局有 12 根外观近似的薯条，编号仅用于程序状态，不直接向玩家显示。
- 两名玩家分别获得暖红和湖蓝两套角色视觉，用于区分身份与回合。
- 服务端随机确定第一位行动玩家；重赛时先手轮换。

### 4.2 秘密调制

每名玩家在自己的设备上完成：

1. 秘密选择一根仍完整的薯条作为整蛊薯条。
2. 从辣椒酱、芥末、酸味汁和黏酱中选择两种调味料；允许重复选择，以产生“加倍”反应。
3. 点击“封装配方”后不可修改。
4. 对方只能看到“对手正在调制”或“对手已准备”，不能看到位置和酱料。

双方都锁定后，进入轮流选择阶段。玩家始终可以在自己的小型状态区看到自己埋藏位置的私密标记；对方客户端不接收该数据。

### 4.3 轮流吃薯条

- 当前玩家在 20 秒内选择一根仍存在的薯条。
- 选择后，服务端判断该位置是否为对方仍有效的整蛊薯条。
- 若命中对方整蛊薯条，当前玩家中毒并输掉本局。
- 若玩家选择了自己埋藏的薯条且该位置不是对方的整蛊薯条，该薯条安全消失，玩家也失去用这根薯条击中对手的机会。
- 若双方选择了同一位置作为整蛊薯条，任何人先吃到该位置都会因为命中对方配方而落败。
- 若双方的整蛊薯条都被各自安全吃掉，服务端立即判定平局，不让玩家继续无意义地清空餐盘。
- 安全选择完成后，回合交给另一名玩家。

### 4.4 超时

- 剩余 5 秒时给当前玩家明显的视觉提醒。
- 20 秒仍未选择时，服务端从剩余薯条中随机替该玩家选择一根，并按正常规则结算。
- 自动选择在双方界面明确标记，避免玩家误以为对手正常操作。

### 4.5 结算与重赛

- 命中后双方同时看到受害者角色的全屏表情特写、配方名称、制作者和胜负结果。
- 表情演出持续约 2.5 秒，可点击跳过，但不能在首帧直接消失。
- 双方都点击“再来一局”后原房间重置，先手轮换；单方点击时显示等待状态。
- 任一玩家离开后，另一方可返回首页重新匹配或创建房间。

## 5. 调味料与表情系统

调味料不改变命中概率和伤害，只决定揭晓演出，避免形成付费战力。

| 调味料 | 基础反应 | 视觉关键词 |
| --- | --- | --- |
| 辣椒酱 | 红脸、冒汗、喷卡通火焰 | 红橙、膨胀、热浪 |
| 芥末 | 鼻酸、流泪、头发竖起 | 黄绿、泪线、弹跳 |
| 酸味汁 | 五官收缩、脸颊凹陷、抖动 | 青柠、挤压、震颤 |
| 黏酱 | 嘴巴粘住、拉丝、含糊挣扎 | 紫粉、拉伸、黏连 |

组合演出按两个调味料依次播放：第一种反应约 0.8 秒，短暂停顿后叠加第二种反应。相同调味料触发“加倍”版本，例如更大的火焰或更长的泪线。首版不实现组合专属数值。

## 6. 用户流程

### 6.1 首页

首页只保留三个对局入口：

1. `快速匹配`：加入真人队列，匹配到第二名玩家后自动建房。
2. `邀请好友`：立即创建房间，显示复制邀请链接和六位数字房间码。
3. `输入房间码`：作为邀请链接失效或不便打开时的兜底。

设置、商城、签到等不属于验证目标的入口不出现。

### 6.2 快速匹配

- 第一个玩家进入等待页，可取消匹配。
- 第二个玩家加入队列后，两人立即进入同一房间。
- 本地原型不伪装真人机器人；只有两个标签同时排队才会成功匹配。

### 6.3 邀请好友

- 创建后立即得到邀请 URL 和房间码。
- 另一标签打开 URL 后直接加入房间，无需再次输入编号。
- 房间满员、编号错误或房间过期时，显示明确原因并返回首页入口。
- 未来接入抖音时，由平台好友邀请面板和私信卡片替换“复制链接”，房间标识仍由服务端生成并校验。

## 7. 界面结构

### 7.1 视觉基调

- 竖屏手机优先，桌面浏览器中居中显示不超过 480 像素宽的游戏舞台。
- 风格为明亮的深夜快餐店：奶油色餐盘、番茄红、芥末黄、湖蓝和深紫背景。
- 薯条需要大、可点、分布略有错落，但不采用任何参考游戏的固定布局或素材。
- 角色采用原创几何卡通脸，不使用真人头像，表情变化通过 CSS 形变和符号特效完成。

### 7.2 主要界面

- 首页：标题、玩法一句话、三个入口。
- 匹配页：对手席位、搜索动画、取消按钮。
- 邀请房：房间码、复制链接、对手加入状态。
- 调制页：餐盘、私密选择标记、四种酱料、两个配方槽、封装按钮。
- 对局页：双方头像与状态、回合提示、20 秒计时环、薯条餐盘、自己的私密毒药提示。
- 揭晓层：受害者脸部特写、酱料粒子、配方名称、胜负、重赛按钮。

## 8. 技术架构

### 8.1 服务端

使用 Node.js HTTP 服务和 WebSocket 实现内存态原型：

- `Matchmaker`：管理快速匹配队列。
- `RoomManager`：创建、查找、回收双人房间。
- `GameEngine`：验证状态转换、保存秘密配方、处理选择、超时和胜负。
- `SessionRegistry`：将标签页会话标识绑定到房间席位，支持短时重连。

服务端是唯一可信状态来源。客户端提交的薯条编号、配方和动作必须经过阶段、身份、回合、剩余选项与重复操作校验。

### 8.2 客户端

使用原生 HTML、CSS 和 JavaScript，保持原型轻量：

- `transport`：连接 WebSocket、发送命令、处理重连。
- `store`：保存当前公开状态和本玩家私密状态。
- `views`：按阶段渲染首页、房间、调制、回合和结算。
- `effects`：根据配方驱动表情和粒子动画。
- `platformAdapter`：本地实现复制链接；未来替换为抖音邀请接口。

同一浏览器的两个标签使用各自的会话存储标识，确保能模拟两个独立玩家。

### 8.3 消息数据原则

- 广播状态只包含双方都可见的数据，例如昵称、准备状态、剩余薯条和当前回合。
- 玩家私密消息只包含自己的埋藏位置和配方。
- 对方配方只在命中结算后公开。
- 客户端刷新或 WebSocket 自动重连后，服务端按身份重新发送相同权限范围内的状态。

## 9. 异常处理

- 非当前玩家点击薯条：客户端不给操作态，服务端仍拒绝命令。
- 重复锁定配方或选择已消失薯条：服务端拒绝并返回可读错误，不改变房间状态。
- 调制阶段掉线：保留席位 30 秒；重新连接后恢复私密选择。
- 对局阶段掉线：暂停计时并保留 30 秒；超时未回归则判离线玩家负。
- 邀请房无人加入：10 分钟后自动回收。
- 两人都离线：立即取消计时，短暂保留后回收房间。
- 服务重启：原型房间清空，客户端显示连接丢失并可返回首页。

## 10. 测试与验收

### 10.1 自动测试

- 匹配队列：两名玩家配成同一房，取消后不再匹配。
- 房间：创建、通过编号加入、满员拒绝、过期拒绝。
- 调制：双方秘密数据隔离、重复锁定拒绝、双方准备后进入回合。
- 回合：仅当前玩家可选、已移除薯条不可重复选、安全选择换手。
- 胜负：命中对方毒药、吃掉自己毒药、双方同位置、双毒失效平局。
- 超时：随机选择仍存在的薯条并正常结算。
- 重赛：双方确认后重置、先手轮换、旧配方清除。
- 断线：短时重连恢复，宽限期后判负。

### 10.2 浏览器验收

1. 启动服务后在两个标签打开首页。
2. 验证两个标签快速匹配进入同一房间。
3. 返回首页，通过邀请链接再次进入同一房间。
4. 两边选择不同配方并锁定，确认互相看不到对方秘密。
5. 轮流选择直至命中，确认双方同步显示正确受害者和配方表情。
6. 双方发起重赛，确认餐盘、秘密和先手全部重置。
7. 在手机尺寸和桌面尺寸检查点击区域、文字溢出和动画表现。

## 11. 完成标准

- 新用户无需说明即可在 30 秒内完成匹配或邀请并进入调制。
- 两个标签之间没有秘密位置或配方泄漏。
- 一局可从调制完整进行到命中、表情揭晓和重赛。
- 辣椒、芥末、酸味和黏酱至少各有一种清晰可区分的表情效果。
- 自动测试全部通过，核心双标签流程通过真实浏览器验收。
- README 提供一条启动命令和清晰的双标签验收步骤。
