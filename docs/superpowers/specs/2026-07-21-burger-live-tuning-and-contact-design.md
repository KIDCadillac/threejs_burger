# 汉堡实时调参与盘面接触设计

## 目标

让测试者在手机游戏内直接调整七种汉堡食材的主要三维比例，并把满意参数复制给开发者。同时建立不可被调参破坏的接触规则：最底层食材必须贴住盘面，相邻食材不得出现正向空气间隙。

## 范围

- 七种食材按“食材类型”分别保存参数：下层面包、肉饼、芝士、番茄、生菜、酸黄瓜、上层面包。
- 每种食材开放四项安全参数：宽度 `scaleX`、厚度 `scaleY`、深度 `scaleZ`、向下贴合量 `sinkY`。
- 全局开放料理台展示比例 `presentationScale`。
- 参数实时应用于当前食材、重复实例、拖动预览、插入动画、选中外壳、酱料附着与之后新取出的同类食材。
- 参数保存在当前浏览器，并能复制为稳定 JSON、恢复当前食材默认值或恢复全部默认值。
- 不开放顶点、分段数、材质参数及原始 `stackMinY/stackMaxY`。这些参数会使几何失效或破坏接触约束，不适合作为手机实时调参入口。

## 默认值与限制

配置使用版本化结构：

```json
{
  "version": 1,
  "global": { "presentationScale": 0.72 },
  "ingredients": {
    "bottom-bun": { "scaleX": 1, "scaleY": 1, "scaleZ": 1, "sinkY": 0.012 },
    "patty":      { "scaleX": 1, "scaleY": 1, "scaleZ": 1, "sinkY": 0 },
    "cheese":     { "scaleX": 1, "scaleY": 1.45, "scaleZ": 1, "sinkY": 0.008 },
    "tomato":     { "scaleX": 1, "scaleY": 1, "scaleZ": 1, "sinkY": 0 },
    "lettuce":    { "scaleX": 1, "scaleY": 1.55, "scaleZ": 1, "sinkY": 0.008 },
    "pickle":     { "scaleX": 1, "scaleY": 1, "scaleZ": 1, "sinkY": 0 },
    "top-bun":    { "scaleX": 1, "scaleY": 1, "scaleZ": 1, "sinkY": 0.008 }
  }
}
```

- `presentationScale` 限制在 `0.55–0.90`。
- `scaleX/scaleZ` 限制在 `0.60–1.60`。
- `scaleY` 限制在 `0.40–2.50`。
- `sinkY` 限制在 `0–0.18` 场景单位。
- 非数字、超范围和旧版本数据在载入时归一化，不得让页面启动失败。

## 盘面与堆叠接触

白色盘子是高度 `0.16`、中心 `y=0.24` 的圆柱，因此当前顶面是 `y=0.32`。旧的首层基准 `dropAnchor.y=0.38` 会制造固定 `0.06` 的空隙。

料理台负责从盘子几何包围盒和位置派生 `supportY`，并让 `dropAnchor` 与它一致。堆叠布局从 `supportY` 开始，不再维护另一份手填高度。每层按其真实接触平面、Y 缩放与 `sinkY` 计算位置：

```text
layerY = supportCursor - stackMinY * scaleY - sinkY
nextCursor = layerY + stackMaxY * scaleY - baseOverlap
```

这样最底层允许极轻微压入盘面，而不会浮空；后续层的 `sinkY` 表示压入下一层的视觉量。

## 调参界面

- 页头增加“参数”入口，打开适配手机安全区的底部面板。
- 面板顶部用食材标签切换七种食材。
- 四项参数均提供滑杆、数值输入和当前值，拖动时实时预览。
- 全局比例独立放在“整体”区域。
- 面板提供“复制参数”“恢复当前”“全部恢复默认”操作。
- 复制成功后显示简短确认；剪贴板 API 不可用时，显示已选中的 JSON 文本供手动复制。
- 调参面板只改变本机浏览器的测试参数。开发者收到截图或 JSON 后，再将满意值固化为公开默认值。

## 组件边界

- `burger-tuning.mjs`：默认配置、范围归一化、深冻结、localStorage 载入/保存和稳定 JSON 输出。
- `cooking-tuning-panel.mjs`：面板 DOM、滑杆与数字输入同步、复制和重置，不直接操作 Three.js 对象。
- `cooking-solo-stage.mjs`：唯一应用参数的位置，提供 `getTuning()` 与 `setTuning()`；所有目标缩放和堆叠高度统一从这里计算。
- `cooking-workbench-3d.mjs`：提供由盘子几何派生的 `prep.supportY`。
- `cooking-solo-app.mjs`：连接面板、持久化和 Stage API。

## 状态与动画

调参时先结束当前拖动、插入动画和临时预览，再按新参数同步全部权威变换并重新计算相机。重复实例通过 `state.instances[instanceId]` 映射到食材类型，因此同类食材共享一组参数。

选中外壳和酱料位于食材组的局部坐标内，会跟随 X/Y/Z 缩放。非等比 Y 缩放可能轻微压扁已有酱料管线，本阶段接受该视觉结果；后续若需要保持酱料圆截面，再单独重建酱料几何。

## 错误处理

- localStorage 不可用、隐私模式抛出 `SecurityError` 或 JSON 损坏时，静默回退默认值。
- 输入值在进入 Stage 前统一截断到安全范围。
- 复制失败不丢失参数，改用可选中文本回退。
- 调参不得改变料理历史、层顺序、库存、酱料记录或完成状态。

## 验收

- 最底层面包的可见底面与盘子顶面间隙不大于 `0.005`，压入不超过 `0.03`。
- 放入动画的每个采样帧都不得把底层面包抬离盘面。
- 七种食材的 X/Y/Z 比例和贴合量均能独立实时改变。
- 重复实例继承所属食材类型参数，未来新取出的实例也一致。
- 芝士和生菜的默认厚度高于当前线上版本，同时仍明显薄于面包和肉饼。
- 20 层调厚后仍能完整进入普通与聚焦相机画面。
- 页面刷新后恢复本机参数；坏 JSON 和被禁止的 localStorage 不影响启动。
- 参数 JSON 顺序稳定，可直接通过截图或复制文本复现同一外观。
