# 《女巫的毒药》可操作食物实玩版设计

## 目标

在不改动现有匹配、好友房、电脑对手和隐藏配方规则的前提下，做出一条可在手机上完整游玩的卡通写实流程：秘密部署时操作食物，同桌阶段观察表情并选择公共零食，中招后观看切面回放。

## 已确认的体验

- 部署阶段使用第一人称卡通写实操作台。
- 食物是可以拿起、切开或掀开、加入调料、合回去的实体道具。
- 部署期间对手看不到所选食物和调料，只能看到玩家的表情和搞怪动作。
- 部署结束后切换到双人同桌视角，桌上零食双方公用，不按玩家颜色归属。
- 选食阶段双方都能看到当前瞄准位置、角色表情和动作。
- 中招时先演出角色反应，再回放食物打开后的切面和隐藏调料。
- 首个实际案例优先完成单人对电脑，同时继续兼容快速匹配和好友邀请。

## 视觉方案

采用卡通写实的烹饪模拟器质感：食物有厚度、切面、烘烤纹理和酱料光泽，环境使用温暖餐厅灯光，人物采用夸张但不幼稚的女巫角色。概念图作为场景氛围图使用；真实点击区域、状态提示和按钮仍由 HTML/CSS 渲染，保证手机触控、响应式布局和可访问性。

## 客户端结构

### 秘密部署

`renderMixing` 显示操作台和公共零食。选择零食后，玩家必须点击“切开/打开”，才能选择两份调料。选择完成后点击“合上并伪装”，播放私密下料演出并提交原有 `recipe.lock` 指令。

客户端新增一份仅控制表现的部署状态：

- `selectedFry`: 已选择的公共位置。
- `deploymentOpened`: 当前食物是否已经打开。
- `selectedSauces`: 已加入的两份调料。

这些状态不向对手广播；服务端仍只接收最终位置和配方。

### 同桌选食

`renderTurn` 使用双人同桌场景，公共盘仍由服务端 `snacks` 与 `remainingFries` 驱动。第一次点击发送 `snack.aim`，玩家可以观察对方表情并改选一次，然后点击确认吃下。搞怪动作继续使用现有 `gesture.send`。

### 揭晓与回放

保留现有胜负结算协议。中招时先显示角色表情失控，再显示被打开的食物、两份调料和部署者，最后展示胜负卡片。

## 新手引导

首次进入单人练习时使用页内教练提示，不阻断连接：

1. 指向公共零食，提示先选一件。
2. 指向打开按钮，说明对手看不到食物。
3. 指向调料瓶，要求加入两份调料。
4. 指向合上按钮，完成部署。
5. 同桌阶段提示先瞄准、观察表情、再确认吃下。

引导可以跳过，并通过本地存储记录完成状态。

## 错误与降级

- 场景图加载失败时保留渐变背景、可点击零食和所有文字操作，不影响游戏。
- WebSocket 未连接时沿用现有提示，按钮不会提交无效操作。
- 对手掉线时沿用服务端暂停和超时结算。
- 开启减少动态效果的设备会缩短或取消切开、挤料、咬下动画。

## 测试

- 静态客户端测试检查新部署步骤、同桌场景、教程标记和场景资源存在。
- 既有领域、协议、服务和 WebSocket 测试必须继续通过，证明隐藏配方和联网规则未被破坏。
- 使用 390×844 手机视口完成单人练习主路径，检查没有横向溢出、控制台错误或小于 44px 的主要触控目标。
