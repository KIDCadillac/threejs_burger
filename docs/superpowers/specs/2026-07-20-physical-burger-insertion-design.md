# 3D 汉堡物理感塞入交互设计

日期：2026-07-20

## 目标

把当前偏工具式的拖放改造成具有游戏手感的三维食物组合：玩家可以大范围环绕和缩放料理台；拿起食材时得到直接的三维高亮；放到顶部、塞到底部或放回原料格时，不再依赖文字胶囊提示，而由汉堡本身的让位、压缩、弹出和落定动画解释结果。

本轮只改善自由镜头、接触式堆叠、拿取反馈和三类落位动画，不加入刚体物理引擎、新菜谱、角色、多人或结算反应。

## 已确认的根因

1. 料理模式向控制器传入了 `±0.78` 的水平角度和 `0.50–0.95` 的俯仰范围，明显小于通用控制器范围，所以玩家无法按喜好绕到料理台侧后方或从更高、更低的角度观察。
2. 食材显示比例统一为 `0.72` 后，堆叠算法仍用未缩放的 `halfHeight` 累加 Y 坐标。可见食材只有原厚度的 72%，但中心间距仍按 100% 厚度计算，因而每一层都留下空隙；七层累计后形成明显的悬空汉堡。
3. 控制器虽然设置了 `cookingInteractionSelected`，模型没有把该状态渲染成光圈、提亮或其他可见效果，因此拿起食材主要只有位移变化。
4. 当前拖动反馈依赖页面中央的 `.cooking-drop-intent` 文字胶囊。它能解释规则，但看起来像“顶部 / 底部 / 放回”的按钮选择，与直接操作三维食物的目标冲突。
5. 当前吸附动画只对每一层做相同的 190ms 位置插值。它没有区分顶部放置、底部塞入和回料格，也没有整叠汉堡的让位、冲击与回弹。

## 方案比较

### 方案 A：确定性弹簧编舞（采用）

继续使用现有 Three.js 场景和不可变料理状态，只为视觉层增加可取消的分阶段时间线。落位结果仍由规则决定，动画负责表现“预备—冲击—过冲—稳定”。优点是结果可预测、移动端性能稳定、可以逐帧测试；缺点是需要为顶部、底部和回料格分别设计关键帧。

### 方案 B：刚体物理

为食材增加碰撞体和重力，让汉堡真实坠落。自由度高，但薄片食材容易穿模、抖动或翻飞，底部插入也难以稳定复现，并增加移动端体积和性能成本。本轮不采用。

### 方案 C：只让当前食材弹跳

保持其他层静止，仅让新食材缩放和上下过冲。实现成本最低，但底部插入时没有“整叠让位”的重量感，也不能仅靠动画清晰说明插入位置。本轮不采用。

## 详细交互

### 1. 自由环绕镜头

- 水平旋转改为完整环绕，不在料理模式内限制为正面小扇区；角度使用周期归一化，使连续拖动不会卡在左、右边界。
- 俯仰范围放宽到接近桌面低角度和接近俯视的高角度，但仍不允许翻到桌底或倒置。
- 双指缩放保留宽距离范围，玩家可以贴近食材看切面，也能拉远观察整张料理台。
- 保留“镜头复位”，任何自由观察都可一键回到默认构图。
- 单指上下和左右方向继续沿用上一版已经确认的跟手方向，灵敏度不重新加快。

### 2. 接触式堆叠

- 所有堆叠高度统一使用 `scaledHalfHeight = halfHeight * LAYER_PRESENTATION_SCALE`。
- 相邻层中心距离等于两层缩放后半高之和，再减去很小的视觉重叠量，使不规则生菜、芝士和面包看起来压在一起而不是悬空。
- 调味轨迹仍附着在各自食材局部坐标，不因堆叠重新计算而脱落。
- 展开查看如果保留，只能由玩家主动触发；普通装盘、完成料理和重新排序都必须默认恢复接触状态。

### 3. 拿取高亮

- 指针选中食材后，为该食材显示一圈暖黄色三维光环，并把食材轻微提亮。
- 拿起的最初约 90ms 做一次小幅“挤压—弹起”：Y 方向略压缩，X/Z 略扩张，随后回到统一展示比例；这只是短暂反馈，不改变最终大小。
- 拖动期间光环保持可见，松手、取消、页面隐藏或 WebGL 上下文丢失时必须清除。
- 高亮属于食材本身，不使用覆盖在页面中央的按钮或文字条。

### 4. 拖动中的三维预演

- 移除 `.cooking-drop-intent` 文字胶囊及其顶部、底部、原位文案。
- 食材进入顶部意图区时，当前汉堡顶部轻微下压，并在实际落点上方出现薄的暖色落位光环。
- 食材进入底部意图区时，已装食材整体抬起少量距离，底层下面出现暖色缝隙，表示将为新食材让位。
- 食材进入自己的原料格磁吸区时，只高亮该原料格边框；其他料格不会亮。
- 离开有效区域后，所有预演立即回到当前真实状态。预演不得修改料理顺序或写入历史记录。

### 5. 顶部弹入动画

顶部放置采用四段确定性时间线，总时长约 300ms：

1. 预备：已装汉堡向下压缩少量，目标食材保持在堆叠上方。
2. 冲击：目标食材快速落到最终接触位置以下约 6% 自身厚度。
3. 过冲：目标食材向上弹起约 12% 自身厚度，同时整叠汉堡恢复。
4. 稳定：目标食材与下层完全贴合，位置和统一比例精确回到状态模型目标。

冲击瞬间提供一次极轻的短震动。开启“减少动态效果”时直接落定，不执行过冲。

### 6. 底部塞入动画

底部放置使用明显不同的编舞，总时长约 380ms：

1. 让位：已有汉堡整体向上抬起，底部打开一层食材厚度的空间。
2. 塞入：新食材先移动到汉堡中部的视觉入口，随后快速向下穿行到最终底层位置。穿行期间旧层保持整体抬起，不与新层交叉闪烁。
3. 弹出：新食材从底部最终位置略向下过冲，再向上“嘣”地弹回；旧层同时落到新底层上。
4. 稳定：所有层按照接触式堆叠目标重新对齐，任何临时偏移归零。

这段动画只改变临时显示变换，料理顺序在松手时一次性提交，撤销仍只产生一个历史步骤。

### 7. 放回原料格动画

- 拖入自己的磁吸区时原料格高亮。
- 松手后食材先略微高于格底，再快速压入格中，最后做一次很小的垂直回弹。
- 回弹结束时位置、旋转和统一比例必须精确等于原料格目标。
- 无效位置松手仍回到拖动前状态，但使用较柔和的回滚，不播放成功冲击震动。

## 动画架构

- 新增一个纯函数时间线模块，输入动画种类、起始时间、食材厚度和减少动态效果设置，输出当前阶段、归一化进度以及弹簧/压缩系数。
- `cooking-solo-stage.mjs` 负责把时间线采样结果映射到新食材和已有食材的临时位置；料理状态和最终目标变换仍是唯一真相来源。
- 同一层开始新拖动、工具栏旋转、撤销、重置、继续编辑或页面生命周期取消时，旧动画必须立即取消，并从权威状态重新同步。
- 拖动预演与落位动画互斥：松手提交后先清除预演，再启动对应的落位时间线。
- 不创建每帧新几何体或材质；高亮光环预先创建并复用，动画帧只更新可见性、位置、旋转和缩放。

## 错误与降级

- 减少动态效果模式直接使用接触式最终位置，只保留静态高亮。
- 振动 API 缺失或抛错时静默忽略，不影响落位。
- 动画回调、页面隐藏、指针取消和 WebGL 上下文异常必须回收高亮与临时偏移。
- 任意动画计算得到非有限数值时，放弃该帧编舞并调用权威状态同步，不能让食材留在空中。

## 验收标准

1. 料理模式不再把镜头锁在正面小范围；玩家能绕到侧后方、从低角度和高角度观察，并能复位。
2. 七层普通汉堡中每两层都视觉接触，不出现随层数累计的空隙。
3. 拿起任意食材时，只有该食材显示三维高亮和短暂弹起反馈；取消或松手后高亮清除。
4. 页面上不再出现“放在最上层”“塞到最下层”“放回原料格”的文字胶囊。
5. 顶部落位从上方冲击并回弹；底部落位使旧层整体让位，新食材从中部进入并在底部弹出；两者无需文字也能看出结果差异。
6. 放回原料格在边缘磁吸区仍容易成功，并播放独立的小回弹。
7. 动画期间最终比例不跳变，结束位置与状态模型严格一致；撤销和重置不会留下临时偏移。
8. 390×844 手机尺寸下所有操作可用，WebGL 控制台无错误，完整 Node 与 Python 测试通过。
