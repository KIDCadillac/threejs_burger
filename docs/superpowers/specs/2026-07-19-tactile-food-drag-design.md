# 卡通写实食物与拖拽加料设计

## 问题

当前实玩版的公共食物由 CSS 几何形状组成，缺少真实材质；食物打开后只有简单色带；调料依赖点击按钮且固定两份，导致部署阶段的操作感不足。

## 方案选择

采用分层 2.5D 食物素材，而不是继续完善 CSS 图形或立即引入完整 WebGL 三维场景。素材从已经确认的卡通写实概念图中提取，并为近景操作增加打开、分层和酱料覆盖效果。该方案在手机小游戏性能、加载体积和视觉质量之间最平衡；完整三维自由切割留到后续版本。

## 食物表现

- 公共盘的薯条、鸡块、甜甜圈、曲奇、洋葱圈和糯米团改用卡通写实 PNG 素材。
- 小图用于公共盘，放大图用于部署操作台和回放。
- 打开状态将同一食物分成上下两层并拉开，中间显示内部切面，而不是只改变边框。
- 每次加料在内部切面上增加一条对应颜色的酱料层，最多显示四层。
- 场景图加载失败时仍保留名称、点击区域和简化颜色占位。

## 拖拽交互

使用 Pointer Events 统一支持 iPhone、Android 和鼠标：

1. 玩家按住调料瓶后产生跟手的瓶子影子。
2. 拖到打开食物的内部时，食物高亮并出现“松手加入”提示。
3. 在食物内部松手后才加入调料，并播放挤料线条动画和轻微震动反馈。
4. 在食物外松手则取消，不改变配方。
5. 点击瓶子保留为键盘和辅助功能的备用操作，但界面文案主推拖拽。

拖拽中的坐标和影子只属于本地表现状态，不通过 WebSocket 同步。

## 配方规则

- 配方从固定两份改为 1～4 份。
- 同一种调料可以重复加入，顺序保留。
- 玩家加入第一份后即可完成伪装，也可以继续加到四份。
- 达到四份后调料架锁定；删除任一配方层后恢复拖拽。
- 服务端验证 1～4 份且每份必须属于已知调料，避免客户端绕过上限。
- 电脑首版仍默认选择两份，保持公平且不额外延长等待。

## 回放与反应

回放按加入顺序逐层显示最多四份调料。角色反应先播放第一种效果，再同时叠加剩余效果；结果卡完整列出所有调料。重复调料显示数量并增强同类反应。

## 测试

- 领域测试覆盖 1 份、4 份合法，0 份、5 份非法。
- 客户端静态测试覆盖 Pointer Events、拖拽影子、落点检测、四个配方槽和真实食物素材。
- 390×844 浏览器实测按住、移动、外部取消、内部释放、删除配方、四份封顶和完成部署。
- 既有隐藏配方、电脑对手、匹配和好友房测试必须继续通过。
