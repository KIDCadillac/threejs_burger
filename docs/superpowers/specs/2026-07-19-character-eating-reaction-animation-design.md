# 角色进食与食物反应动画设计

## 目标

把当前以静态图和简单表情切换为主的回放，升级为完整的“拿取食物—真实咬下—短暂咀嚼—配料触发—全身反应”动作。第一条可玩样片是：普通人物拿起玩家拼好的汉堡，咬出缺口，因辣味后仰喷火，再手忙脚乱地扇嘴。

“女巫的毒药”只是一个玩法模式名，不限制平台主题、角色身份或美术元素。首个角色是穿现代休闲服的普通人物，不出现女巫帽、魔法、药水、坩埚等固定主题符号。以后所有普通人物、主播形象和角色皮肤都复用同一套动作系统。

## 方案选择

### 采用：2D 骨骼角色、可拆食物与独立特效层

角色拆成头、躯干、上臂、前臂、手、五官和头发等可动画部件；汉堡继续保持面包、肉饼、蔬菜、酱料等独立层；火焰、热气、汗珠和眼泪属于单独特效层。动作通过统一时间轴和事件点组合，而不是把一张 GIF 或表情图片贴到人物脸上。

这个方案能同时满足手机性能、角色换皮和夸张全身动作。动作骨架可复用，角色外观、衣服、发型、肤色和表情贴图可以独立替换。

### 未采用：逐帧图片序列

逐帧动画可以获得更细腻的手绘效果，但每种角色和反应都需要重画大量帧，包体和制作成本增长较快，不适合作为当前小游戏的第一版基础系统。

### 未采用：完整 3D 角色

3D 角色在镜头、材质和动作复用方面更自由，但首版需要建模、绑定、表情控制器、灯光和移动端渲染优化，周期明显更长。它可以作为验证玩法后的升级方向。

## 动作语言

动作不是单独换脸，而是五个部分连续传递：

1. **手与食物**：角色的手从画面下方或身体一侧伸出，手指包住汉堡，汉堡跟随手腕运动。
2. **食物与嘴**：汉堡到达嘴边时嘴巴先张开；咬合事件发生后，汉堡出现与嘴形对应的真实缺口，并露出内部配料剖面。
3. **嘴与面部**：咀嚼时下颌、脸颊、眼睛和眉毛都有细微动作；触发前保留短暂的强装镇定。
4. **面部与身体**：配料生效后，头、肩、腰和腿依次反应，不能只有五官变化。
5. **身体与特效**：喷火方向跟随嘴部锚点，后仰、衣服摆动、头发延迟和火焰冲击保持同步。

每条反应遵循“预备—爆发—过冲—回落”的动画节奏。动作允许夸张形变，但人物仍然保持现代、精致、非古早表情包的视觉品质。

## 第一条样片时间轴

完整时长约 4 秒：

| 时间 | 动作与事件 |
| --- | --- |
| 0.00–0.35 秒 | 视线落到汉堡，手伸向餐盘，手掌预先张开。 |
| 0.35–0.70 秒 | 手指收拢并抓住汉堡，汉堡轻微下压后被拿起。 |
| 0.70–1.10 秒 | 手腕把汉堡送向嘴边，头部略微前探，嘴巴张开。 |
| 1.10–1.35 秒 | 咬合事件：出现咬痕和内部剖面，掉落少量面包屑。 |
| 1.35–1.80 秒 | 咀嚼两次，角色试图保持正常；配料暂不揭晓。 |
| 1.80–2.05 秒 | 突然停顿，瞳孔收缩，肩膀抬起，脸色迅速变红。 |
| 2.05–2.75 秒 | 辣味爆发：角色后仰，嘴部喷出卡通火焰，头发和衣服受冲击摆动。 |
| 2.75–3.60 秒 | 火焰停止，角色双手快速扇嘴、跺脚，冒出热气和汗珠。 |
| 3.60–4.00 秒 | 动作回落，角色喘气并瞪向对手，为下一回合恢复待机姿势。 |

## 食物与配料驱动

每份食物保存可见的结构层和隐藏的配料标签。部署者能看到自己拖入的配料；对手只在咬下并进入反应阶段后看到结果。

反应由配料标签而不是食物名称直接决定：

- **辣味**：脸红、后仰、喷火、扇嘴；强度控制火焰长度和持续时间。
- **芥末**：鼻子发冲、捏鼻、快速摇头、原地乱蹦。
- **酸味**：五官收缩、肩膀打颤、身体拧紧。
- **苦味**：强行吞咽、舌头伸出、身体逐渐瘫软。
- **黏性**：嘴部暂时粘住，双手拉扯后弹开。

多个配料不同时播放全部特效。系统先选强度最高的配料作为主反应，再把其余配料转成一个短促的追加动作。例如辣椒加芥末先喷火，火焰结束后追加捏鼻摇头。这样既体现组合配方，又不会让画面失去可读性。

## 动画组件边界

- **CharacterRig**：角色骨骼、锚点、五官状态和待机/拿取/咀嚼/反应片段。
- **FoodAssembly**：食物的独立层、抓取锚点、嘴边锚点、咬痕状态和剖面显示。
- **ReactionResolver**：把隐藏配料列表转换为主反应、追加反应和强度等级。
- **ReactionTimeline**：按时间驱动动作片段、咬合、揭晓、特效和声音事件。
- **EffectLayer**：火焰、烟、热气、汗珠、眼泪、面包屑等可复用效果。
- **ReplayController**：确保部署者和食用者看到相同结果，并允许完整重播一次。

这些组件只通过明确的事件和数据通信。食物外观、人物皮肤或特效素材可以单独替换，不需要重写游戏规则。

## 声音与触觉反馈

- 抓起和咬下使用短促、清脆的食物音效。
- 配料触发前保留约 0.2 秒静音，强化悬念。
- 喷火使用卡通化“呼”声，不使用痛苦惨叫。
- 手机端在咬合和反应爆发两个事件各提供一次短振动；不支持振动时静默降级。

## 性能与降级

- 第一版同屏只播放一名角色的主反应，目标是在常见手机浏览器上保持流畅。
- 角色部件和特效优先打入纹理图集，限制同时存在的粒子数量。
- 低性能设备减少面包屑、烟雾和热气粒子，但保留抓取、咬合、喷火和扇嘴的主体动作。
- 若个别素材加载失败，仍播放骨骼动作并使用简化色块特效，不阻塞回合结算。

## 内容安全与原创边界

- 借鉴“小丑捏鼻子摇头”等表情包的动作节奏，不复刻其角色造型、五官或原动图帧。
- 反应作用于角色自身，不出现扇对方巴掌、踢人或鼓励现实伤害的行为。
- 使用夸张卡通特效表达辣、酸、苦和臭，不表现真实中毒、严重受伤或呕吐物。

## 测试与验收

自动化测试覆盖：

- 配料组合能稳定解析为同一个主反应和追加反应。
- 咬合事件只触发一次，并把完整汉堡切换为带缺口状态。
- 火焰始终绑定嘴部锚点，不因角色换皮漂移。
- 回放期间无法重复结算，播放完成后正确进入下一回合。
- 低性能降级只减少装饰特效，不删除核心动作事件。

首条样片通过以下人工验收才算完成：

1. 能清楚看到手抓住汉堡，而不是汉堡自行漂浮。
2. 汉堡被咬后有真实缺口和可见配料剖面。
3. 咀嚼到喷火之间有明确停顿和表情转折。
4. 喷火时头、肩、腰、头发、衣服和手都有连锁反应。
5. 喷火结束后角色会扇嘴并逐渐恢复，不是突然切回静态图。
6. 整条动画在手机竖屏上主体清晰，按钮不会遮挡手、汉堡或火焰。

## 第一阶段范围

第一阶段只制作一名普通角色、一份可分层汉堡和一条辣味喷火反应，先验证动作品质和手机性能。其他人物皮肤、食物、配料反应、在线同步和商业化入口不在这条样片的范围内；样片通过验收后，再按同一结构批量扩展。
