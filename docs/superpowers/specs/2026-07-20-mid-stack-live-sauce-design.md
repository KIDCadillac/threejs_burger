# 汉堡夹层插入与实时酱料交互设计

## 目标

修复自由料理台在手机上的四类交互问题：汉堡只能插入顶部或底部、选中和落点提示不清晰、插入时预备区食材被错误带动、酱料穿模且只在松手后出现。

本轮只改自由料理台的食材插入、选中反馈和酱料绘制，不改变七层完成条件、食材种类、教程主流程、相机自由旋转、撤销和重置语义。

## 已确认的根因

1. `resolveSoloLayerDrop` 只根据餐盘前后两段返回索引 `0` 或 `assembledCount`，数据结构虽然接受任意 `targetIndex`，指针交互却永远无法产生中间索引。
2. 食材选中和落点都使用尺寸较大的黄色圆环；圆环脱离食材轮廓，在俯视和侧视角下容易被理解为酱料或碰撞范围。
3. 插入预览和落地动画使用整栈位移，没有建立“本次受影响食材集合”这一明确边界，也没有在动画帧中恢复无关食材的权威预备区姿态。取消、连续拾取和旧动画交接时，无关食材可能保留临时位移。
4. 瓶子拖动期间只生成一条位于全局预览根节点下的临时管线，并把瓶嘴和命中点接成同一条管；正式酱料网格直到松手、瓶子回座后才创建。
5. 正式酱料管的表面抬升量为管半径的 `0.7` 倍，小于管半径，因而部分管体必然进入食材模型。

## 交互设计

### 1. 连续插槽与夹层插入

餐盘在前后方向形成 `assembledCount + 1` 个等宽插槽。靠玩家的一端对应索引 `0`，最远端对应索引 `assembledCount`，中间区间依次对应所有夹层索引。

例如当前有两层食材时，餐盘被分成三个可选区：

- 前区：插到两层下方，`targetIndex = 0`；
- 中区：插到两层之间，`targetIndex = 1`；
- 后区：放到两层上方，`targetIndex = 2`。

指针跨越插槽边界时立即更新目标索引。已经在汉堡中的食材重新拖入时，先从临时顺序中移除自身，再基于剩余层数计算插槽，避免索引偏移。

### 2. 缝隙预览与插入动画

当目标索引确定后，舞台用最终权威堆叠高度计算目标缝隙：

- 位于目标索引以下的已装盘食材保持不动；
- 位于目标索引及以上的已装盘食材只抬高“待插食材厚度 + 视觉间隙”；
- 被拖食材保持跟手，不被预览程序抢走；
- 缝隙中心出现贴近汉堡横截面的薄金色光带，光带高度就是最终插入高度。

松手后，被拖食材从当前手持位置滑入缝隙并轻微压缩、回弹；上方食材随后下落贴合。顶部插入是“上方集合为空”的同一算法，底部插入是“上方集合为整栈”的同一算法，不再维护三套分支动画。

动画只允许修改以下对象：被拖食材，以及目标索引及以上的已装盘食材。其余食材每帧使用舞台保存的权威姿态，尤其是仍在预备区的食材必须保持原位。开始新拖动、取消指针、撤销、重置时，都先停止旧动画并恢复权威姿态。

### 3. 选中与落点反馈

移除覆盖范围过大的黄色圆环，改为两级反馈：

- 拾取反馈：食材本体亮度略升、轮廓出现贴身暖金色描边，并有一次约 `1.04` 倍的短促弹起；
- 落点反馈：只在准确插槽高度显示薄光带，上下层张开后就能直接看见目标位置。

预备区格子在鼠标或手指命中时可轻微提亮，但不会推动格子里的其他食材。选中反馈和落点反馈使用不同形状，避免语义混淆。

### 4. 实时贴面酱料

酱料手势拆成两个独立视觉对象：

1. **喷嘴短流**：从瓶嘴垂直到当前食材表面，只表示正在挤压；命中消失时立即消失。
2. **表面轨迹**：挂在实际命中的食材节点下，每采集一个有效点就使用正式酱料相同的表面投影重新生成，因此拖动过程中已经走过的酱料立即保留在食物上。

表面轨迹的中心线高度为 `tubeRadius + clearance`，其中 `clearance` 是一个小的固定安全间隙；这样整根管体都在真实表面之上。轨迹每个采样点都经过食材足迹裁剪和真实上表面投影，不能用未经投影的世界坐标直接生成。

松手时，当前预览轨迹转换为正式酱料记录，画面保持原样，不先删除再突然创建。游戏状态仍以“一次手势一条记录”提交，从而保持撤销、序列化和未来联机同步的原子性。取消手势时只移除本次预览，不写入状态。

当手势从一种食材跨到另一种食材时，结束前一个食材上的预览段并开始新段；两段分别挂在各自食材节点下。食材之后移动、旋转或被咬掉时，酱料继续随所属食材变化。

## 代码边界

### 插槽解析

`app/static/cooking-drop-intent.mjs` 只负责把餐盘坐标、现有层数转换为合法的 `targetIndex` 和插槽元数据。它不读取 Three.js 场景，也不播放动画。

### 插入运动

`app/static/cooking-insertion-animation.mjs` 负责生成与目标索引无关的标准化时间采样值。`app/static/cooking-solo-stage.mjs` 根据 `targetIndex` 计算受影响集合、最终高度，并把采样值应用到具体食材。

### 3D 反馈

`app/static/burger-model-3d.mjs` 提供贴身选中反馈、表面投影和可提升为正式记录的酱料预览。`app/static/cooking-workbench-3d.mjs` 提供单一的插槽光带，不参与堆叠顺序计算。

### 手势控制

`app/static/cooking-interaction-controller.mjs` 负责实时采样瓶嘴命中、按食材分段，并通过明确的预览开始、更新、提交、取消回调与舞台通信。控制器不自行猜测食材曲面高度。

## 数据流

### 食材插入

1. 指针在餐盘平面移动。
2. 插槽解析器返回 `targetIndex`。
3. 舞台从权威顺序移除当前食材，计算下方集合、上方集合和缝隙高度。
4. 舞台只预览上方集合的抬升，并更新缝隙光带。
5. 松手后状态层以 `targetIndex` 写入新顺序。
6. 舞台播放插入与贴合动画，结束时恢复全部权威姿态。

### 酱料绘制

1. 瓶嘴射线命中食材表面。
2. 控制器产生标准化二维食材坐标。
3. 舞台在所属食材上创建或更新实时表面轨迹，同时更新瓶嘴短流。
4. 松手后一次性提交手势的全部分段到游戏状态。
5. 预览轨迹被提升为正式轨迹；若提升失败，恢复原状态并清理本次临时对象。

## 异常与恢复

- 指针离开餐盘、失去捕获或收到取消事件：停止插入预览，恢复所有食材的权威姿态。
- 瓶嘴没有命中食材：结束当前分段并隐藏喷嘴短流，不创建空轨迹。
- 少于两个有效采样点的酱料段：只显示瞬时点状反馈，不写入状态。
- 预览几何创建失败：销毁本次预览资源、瓶子回座、保持先前正式酱料和料理状态不变。
- 撤销、重置或完成料理：先取消活动手势和动画，再应用新快照，避免旧帧覆盖新状态。

## 性能约束

- 继续限制单次酱料轨迹采样点和总轨迹数量。
- 实时轨迹复用一个预览网格和材质；更新几何时释放旧几何，提交后不重复创建等价网格。
- 插入预览只更新被拖食材、上方集合和一条光带，禁止遍历并改写所有预备区食材。
- 手机尺寸下保持现有帧循环和相机手势，不增加全屏 DOM 遮罩。

## 测试与验收

### 自动化测试

1. 两层汉堡的前、中、后餐盘位置分别解析为索引 `0`、`1`、`2`。
2. 已装盘食材重新插入时，中间索引基于移除自身后的层数计算。
3. 夹层预览只抬起目标索引及以上食材；预备区所有无关食材在预览、插入、取消各阶段保持原始变换。
4. 选中反馈贴合食材尺寸，旧的大圆环不再出现；插槽光带记录准确 `targetIndex` 和高度。
5. 第一批两个有效酱料点到达时，所属食材上立即存在可见轨迹，早于指针松开和瓶子回座。
6. 酱料中心线到真实表面的距离至少为管半径加安全间隙，所有采样点均在食材足迹内。
7. 松手提交不产生重复轨迹或可见跳变；取消不增加状态记录。
8. 连续跨越两个食材会产生两个正确归属的分段，移动食材后酱料随之移动。
9. 原有料理状态、撤销、重置、完成流程和资源释放测试继续通过。

### 手机验收

1. 先放两层汉堡，再把第三层拖到餐盘中区，能清楚看到中间缝隙并插入其中。
2. 连续进行底部、夹层、顶部插入，预备区其余食材没有任何弹起或漂浮。
3. 手持食材时能一眼辨认当前对象和准确插槽，但画面没有巨大黄色圆环。
4. 挤酱料时轨迹跟随手指实时出现；未松手时已经能看到走过的路径。
5. 从低角度旋转观察酱料，整条轨迹贴在食物表面，没有穿模和空中长管。
6. 松手回座后，酱料的位置、粗细和形状不发生突变。

## 完成标准

上述自动化测试全部通过，手机视口的真实浏览器验收满足六项条件，控制台无错误，并将更新部署到现有 GitHub Pages 链接：`https://kidcadillac.github.io/threejs_burger/`。
