# 参考汉堡菜谱与自由料理设计

日期：2026-07-21

## 目标

在现有 3D 汉堡料理台中加入一组与麦当劳中国常见牛肉汉堡结构接近的参考菜谱，让玩家一眼知道要做什么，同时保留当前自由拖放、插层、挤酱、重复食材和最多 20 层的玩法。

开发验收可以使用熟悉的参考产品名核对配方；公开商业版本将显示原创名称、原创图标和原创包装，不使用品牌 Logo、角色、门店照片或仿制包装。

## 已选择的方案

考虑过三种做法：

1. **参考菜谱 + 自由料理并存（采用）**：开局选参考菜谱，HUD 显示目标，但不锁定操作。
2. 严格订单模式：错一层就判错，完成后评分。规则清楚，但会破坏当前自由组合的乐趣。
3. 只保留自由模式：开发量最少，但新玩家仍不知道该怎么做，也无法体现不同汉堡的出品差异。

用户已明确选择先按麦当劳风格的命名、出品和配料建立首批菜谱，因此采用方案 1。

## 首批菜谱

以下固体顺序均为从下到上，用于游戏目标与开发验收，不宣称是门店生产 SOP。

| 菜谱 ID | 开发期参考名 | 商业界面原创名 | 固体层序 | 酱料步骤 |
|---|---|---|---|---|
| `classic-beef` | 汉堡包 | 小馆经典牛肉堡 | 下层面包、牛肉饼、酸黄瓜、洋葱、上层面包 | 番茄酱挤在牛肉饼上 |
| `melty-cheese` | 吉士汉堡包 | 融金芝士牛肉堡 | 下层面包、牛肉饼、芝士、酸黄瓜、洋葱、上层面包 | 番茄酱和芥末酱挤在芝士层上 |
| `double-melty-cheese` | 双层吉士汉堡 | 双层融金芝士堡 | 下层面包、牛肉饼、芝士、牛肉饼、芝士、酸黄瓜、洋葱、上层面包 | 番茄酱和芥末酱挤在上层芝士上 |
| `tower-double-beef` | 巨无霸 | 三层高塔双牛堡 | 下层面包、洋葱、生菜、芝士、牛肉饼、中层面包、洋葱、生菜、酸黄瓜、牛肉饼、上层面包 | 下层面包和中层面包各挤一次招牌风味酱 |

主页提供额外的“自由发挥”卡片。自由模式不显示参考进度，其他交互完全相同。

## 数据结构

新增纯前端 `burger-recipes.mjs`。参考菜谱与玩家作品必须是两份独立数据：

```js
{
  id: "classic-beef",
  referenceName: "汉堡包",
  publicName: "小馆经典牛肉堡",
  steps: [
    { id: "bottom-bun-1", kind: "layer", ingredientId: "bottom-bun" },
    { id: "patty-1", kind: "layer", ingredientId: "patty" },
    {
      id: "ketchup-1",
      kind: "sauce",
      sauceId: "ketchup",
      targetLayerSlotId: "patty-1"
    },
    { id: "pickle-1", kind: "layer", ingredientId: "pickle" },
    { id: "onion-1", kind: "layer", ingredientId: "onion" },
    { id: "top-bun-1", kind: "layer", ingredientId: "top-bun" }
  ]
}
```

每个步骤使用唯一 slot ID，才能区分双层菜谱里的两个肉饼或两片芝士。酱料步骤引用已经出现的 slot，不预制轨迹坐标，仍由玩家亲手挤。

玩家状态只记录可选的 `referenceRecipeId`；切换参考菜谱不清空已经摆好的食物，撤销不改变参考菜谱，重置料理时保留当前参考菜谱。

## 单人模式食材与酱料

单人汉堡料理新增两种固体食材：

- `onion`：洋葱粒组合模型，有独立选择面和接触面。
- `middle-bun`：无圆顶、无顶部芝麻、双面烘烤的扁平中层面包。

单人料理酱调整为：

- `ketchup`：番茄酱，红色。
- `mustard`：芥末酱，黄色，复用现有几何与语义 ID。
- `house-sauce`：招牌风味酱，浅橙奶油色。

现有番茄片继续作为自由食材，但不用于首批四个目标菜谱。新 ID 仅注入单人料理台，旧联机“女巫毒药”协议的固定 7 层与四种整蛊酱保持不变。

## 交互与界面

- `cooking.html` 首次进入显示四张菜谱卡和“自由发挥”。
- 支持 `?recipe=classic-beef` 深链；非法参数回到菜谱选择。
- 选择器打开时暂停 3D 操作，关闭或完成选择后恢复。
- HUD 显示当前参考名、固体层进度、酱料步骤和“换参考”。
- 参考菜谱只提示，不阻止换序、插层、移除、重复食材或继续叠到 20 层。
- 完成条件改为至少装好两层，不再硬编码“必须七层”；达到参考菜谱只触发完成提示，不锁死料理。

## 模型与调参

`onion`、`middle-bun` 必须进入与现有食材一致的实时调参系统，支持 X/Z 尺寸、Y 厚度、展示比例和下沉接触量。所有拖拽预览、吸附幽灵、插层动画、最终堆叠和聚焦镜头都读取同一份调参值，避免预览与落点不一致。

中层面包和上下相邻层之间必须用真实接触面计算，不允许出现面包坯浮空；蔬菜、芝士可以有轻微视觉重叠。

## 旧协议隔离

本阶段不修改 Python `recipe_data.py` 和旧联机 `recipe.lock` 协议。现有 solo 序列化包含重复实例的 `layerTypes`，不能提交给旧解析器。

将来若保存自由作品，另建 v2 数据格式，允许 1–20 个唯一实例、重复食材和 0–64 条料理酱轨迹；v1 保持严格兼容。

## 错误处理

- 无效菜谱 ID：回到选择器，不破坏当前作品。
- 菜谱引用未知食材、未知酱或不存在的目标 slot：开发测试立即失败，不在运行时静默忽略。
- 新模型创建失败：显示现有 WebGL 错误面板并完成 stage/面板/反馈记录器清理。
- 菜谱切换或页面关闭时：始终恢复 3D 交互暂停状态。

## 测试与验收

1. 菜谱数据测试：四个 ID、精确层序、重复 slot、酱目标引用顺序、所有食材/酱 ID 合法。
2. 单人状态测试：9 个料盒、新食材可重复、两层可完成、重置保留参考、20 层不回归。
3. 3D 模型测试：洋葱和中层面包是真实几何，接触面正确，可拖放、克隆、移除和插层。
4. 调料测试：三种料理酱颜色和轨迹独立，旧四种整蛊酱默认行为不回归。
5. Stage 测试：9 种食材、3 种料理酱注入成功，新层支持排序、重复、挤酱和聚焦。
6. 页面/App 测试：四张菜谱卡加自由模式、深链、换参考不清空作品、移除所有“七层”硬编码。
7. 真机验收：iPhone/Android 竖屏完成四种参考汉堡，检查面包接触、20 层镜头和触摸可达性。
