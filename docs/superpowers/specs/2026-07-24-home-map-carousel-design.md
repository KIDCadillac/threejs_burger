# 主页地图横滑轮播设计

## 目标

把当前单地图汉堡店主页改成可横向切换的地图大厅。玩家不用离开主页，通过左右滑动即可查看不同餐厅；已开放地图可以进入玩法，未开放地图只展示清楚的预览和筹备状态。

## 地图与状态

首版包含两张地图：

1. **汉堡小馆**：默认地图，状态为已开放，主按钮为“开门营业”，进入 `cooking.html?mode=orders`。
2. **深夜寿司店**：预告地图，状态为“筹备中”，主按钮不可进入，不消耗体力。

当前地图编号保存到 `localStorage`。刷新后恢复玩家最后查看的地图；存储损坏或编号越界时回到汉堡小馆。

## 交互

- 玩家在中央地图场景上左右滑动切换地图。
- 鼠标拖动和键盘左右方向键提供同等操作。
- 横向位移超过场景宽度的 18%，或快速甩动时完成切换；未达到阈值则回弹。
- 第一张地图继续向右拖、最后一张继续向左拖时，只出现轻微阻尼，不循环跳转。
- 场景两侧显示箭头，下一张地图边缘轻微露出；底部显示地图圆点和 `当前/总数`。
- 地图切换时标题、副标题、场景配色、开放状态和主按钮同步更新。
- 顶部资源栏、四个功能入口和底部导航固定不动。
- 从按钮、链接或弹窗开始的触摸不触发地图滑动，避免误操作。

## 视觉

汉堡小馆继续使用明亮的白天快餐店场景。深夜寿司店使用深蓝绿色夜景、木质寿司台、纸灯笼和寿司盘作为明显区分，但保持同一套圆角、描边和按钮语言。

切换动画时长控制在 220–280 毫秒；尊重 `prefers-reduced-motion`，减少动画时直接切换。寿司店主按钮使用灰蓝色禁用样式，并明确显示“寿司店筹备中”，不伪装成可点击入口。

## 代码边界

- `home-map-carousel-state.mjs`：纯状态与滑动判定，包括地图列表、索引规范化、方向切换和拖动阈值。
- `home-lobby-app.mjs`：绑定指针、键盘和按钮事件，保存当前地图并更新页面。
- `index.html`：提供两张地图场景、箭头、圆点、状态文本和主按钮语义。
- `home.css`：负责轨道布局、两套地图视觉、拖动反馈和响应式规则。

## 错误处理

- `localStorage` 不可用时仍可切换，但不保存。
- 指针取消、页面失焦或多指触摸时立即回弹，不留下半张地图。
- 未开放地图的主按钮无跳转地址，并通过 `aria-disabled="true"` 说明状态。

## 测试与验收

- 纯状态测试覆盖：左右切换、边界阻止、损坏存储回退、阈值与快速甩动。
- 页面测试覆盖：两张地图、箭头、圆点、寿司禁用状态、汉堡营业链接和触摸安全区域。
- 全量 Node 与 Python 测试必须通过。
- 公网部署后确认主页、新脚本、样式和汉堡营业入口均返回 200。
