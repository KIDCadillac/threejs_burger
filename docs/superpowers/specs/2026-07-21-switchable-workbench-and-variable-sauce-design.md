# 可切换料理台、可变厚酱料与验收调参设计

## 目标

本轮把自由料理台整理成三个职责清楚的区域，并同时解决酱料像硬塑料管、涂抹没有薄厚和材料参数不易验收的问题：

- 左侧是面包胚区；
- 后排中间是 4 个可自由换料的配料槽；
- 右侧是可自由换料的酱料区；
- 酱料随手势产生薄、厚、堆积和边缘溢出；
- 页面上的参数入口升级为明确的验收工具，所有汉堡材料可分别实时调尺寸和贴合量。

## 已采用的交互方案

### 方案比较

1. **反复点击循环换料**：实现简单，但配料多时要点很多次，也看不到完整可选列表。
2. **每个槽位带折叠翻牌，点击后打开选择面板**：槽位与选择目标对应清楚，手机上也能使用大按钮，推荐采用。
3. **从总配料抽屉拖入槽位**：自由度高，但会和当前拖食材、转镜头手势互相抢操作，现阶段不采用。

因此采用方案 2：每个可切换槽位都有一个小型折叠翻牌。点击翻牌后，该槽位高亮，页面底部展开配料选择面板；选中后面板收起，新配料在原槽位做一次短促弹出动画。

## 料理台布局

### 左侧：面包胚区

- 放置下层面包、中层面包和上层面包三个来源槽，纵向排列在用户标注的左侧黄色区域。
- 每个槽位都有折叠翻牌，可在三种面包胚之间切换；允许多个槽位选择同一种面包胚。
- 默认顺序为下层面包、中层面包、上层面包。

### 后排中间：4 个自由配料槽

- 只保留 4 个等宽槽位，放在用户标注的红色区域。
- 默认是牛肉饼、芝士、番茄、生菜。
- 每个槽位可从牛肉饼、芝士、番茄、生菜、酸黄瓜、洋葱碎中任意选择。
- 允许重复选择，例如四个槽都可以设置为牛肉饼。
- 选择面板显示配料小模型、中文名称和当前库存；当前原型库存继续按每种配料 `999` 计算。

### 右侧：酱料区

- 把现在前排的酱料瓶和底座整体移到用户标注的右侧黄色区域，纵向排列。
- 每个酱料底座都有折叠翻牌，可从当前支持的番茄酱、黄芥末酱、汉堡酱中切换；允许重复选择。
- 更换酱料只替换架上的瓶子，不修改已经涂在食物上的酱料。

### 槽位切换规则

- 物理槽位使用稳定的 `slotId`，槽位当前内容使用独立的 `contentId`，不再用配料 ID 兼任槽位 ID。
- 每个槽位拥有独立的来源实例，因此重复配料不会出现同一个 3D 对象被两个槽位争用。
- 如果玩家正在拿着该槽位的物品，切换前先把本次拖动安全取消，再更换内容。
- 已经装进汉堡的食材、已经提交的酱料轨迹和撤销历史都不受换料影响。
- 自由料理保存最近一次槽位配置，并提供“恢复默认料理台”操作；配方模式只改变进入时的推荐配置，不锁死玩家选择。

## 酱料手感与几何

### 方案比较

1. **可变截面 3D 软酱带 + 轻量堆积场 + 边缘滴落**：能复用现有真实表面投影和咬痕系统，手机成本可控，采用。
2. **贴图笔刷 + 高度贴图**：大面积涂抹便宜，但当前食材没有统一 UV，厚酱和侧边溢出会显得像贴纸。
3. **GPU 流体模拟**：效果最好，但移动端发热、兼容和 WebGL context loss 风险太高，现阶段不采用。

### 薄厚变化

- 新酱料轨迹记录每个采样点的流量值，而不是整笔只有一个平均粗细。
- 拖得快时流量较小，形成更宽但更薄的擦涂；拖得慢或短暂停留时流量增加，形成更厚的酱料堆。
- 支持压感的设备把压感作为附加权重，不把压感当成唯一来源，确保普通手机也能产生明显薄厚变化。
- 每条酱料由扁平、圆润的软带截面生成，不再使用接近圆管的固定截面。

### 重复堆积

- 每个食材实例维护一个运行时 `32 × 32` 轻量酱料高度场。
- 后画的酱料读取已有高度并沿表面法线抬高，因此重复涂同一区域会逐步变厚，不会互相穿插或闪烁。
- 高度场可以由已保存的轨迹确定性重建，因此不需要额外写入存档，也能正确支持撤销、删除和回放。

### 边缘溢出

- 手势划出食材边缘时不立刻截断，而是继续锁定本次命中的食材。
- 顶面软酱带延伸到真实边界，超出边界的距离、停留时间和流量共同决定侧面滴落长度。
- 滴落部分与顶面软酱带属于同一几何，接缝连续，不增加额外绘制次数；滴落方向沿食材侧面向下，不穿入食材内部。

### 数据兼容与性能

- 酱料记录在现有 `amount` 和 `points` 之外增加可选的逐点 `flows`；旧记录没有 `flows` 时，自动用 `amount` 补齐。
- 单段仍限制 24 个点，但达到上限后自动开启连续新段，并复用上一段末点，手势不会画到一半停止。
- 实时预览改为复用同一个动态几何并原位更新；松手时直接把预览转成正式轨迹，不删除后重建。
- 继续维持最多 64 条正式轨迹和移动端约 30k 三角形预算。

## 验收调参

- 顶部“参数”改名为“验收调参”，避免用户误以为只是系统设置。
- 面板继续覆盖 9 种材料：下层面包、牛肉饼、芝士、番茄、生菜、酸黄瓜、洋葱碎、中层面包、上层面包。
- 每种材料开放：横向尺寸 X、厚度 Y、纵向尺寸 Z、贴合量；所有数值现场修改、3D 画面立即生效。
- 同一种材料的所有重复实例共享参数；新从槽位拿出的实例也使用最新值。
- 增加酱料验收区：基础铺开宽度、厚度倍率、停留堆积速度、边缘滴落灵敏度。
- 参数保存在当前浏览器，支持恢复当前材料、全部恢复默认，以及复制完整 JSON。用户只需发送截图或复制的 JSON 即可固定最终默认值。
- 参数均限制在安全范围内，不能通过面板破坏网格、接触约束或手机性能预算。

## 状态与组件边界

- 新增纯状态模块管理 `slotId -> contentId`、允许选项、默认配置、重复选择和本地持久化。
- `cooking-workbench-3d.mjs` 只负责三块区域、稳定槽位、翻牌锚点和高亮，不决定某槽里是什么。
- `cooking-solo-stage.mjs` 负责根据槽位配置创建/替换来源实例，并保证已装盘内容不受影响。
- `condiment-tools-3d.mjs` 从“一个酱料 ID 对应一个固定底座”改为“一个工具槽对应一个当前酱料瓶”。
- `cooking-interaction-controller.mjs` 负责连续采样速度、停留、压感和边缘意图；不自行生成最终几何。
- `burger-model-3d.mjs` 负责可变截面、堆积高度和溢出几何，并保持现有表面投影、咬痕和序列化兼容。
- DOM 选择面板负责大触控目标、中文名称、库存和键盘可访问性；3D 翻牌只负责指出是哪一个槽位。

## 异常与恢复

- 切换槽位、打开验收调参、页面失焦、WebGL context loss 或指针取消时，先取消当前拖动/涂抹，再改变配置。
- 选择面板关闭但未选择时不改变槽位。
- 本地配置损坏或版本不兼容时回到默认布局和默认参数，不阻止游戏启动。
- 酱料预览失败时清理本次临时几何，保留之前已经提交的轨迹与料理历史。

## 验收标准

1. 左侧只放面包胚来源，后排中间正好 4 个自由配料槽，右侧只放酱料瓶；手机竖屏无遮挡。
2. 每个槽位都能通过自己的折叠翻牌更换内容；允许重复选择，同一种配料可同时存在于多个槽位并独立取用。
3. 更换槽位不会删除已装盘食材、已画酱料、撤销历史或库存记录。
4. 同一次酱料手势能明显出现薄段和厚段；停留能堆高，重复覆盖不会穿模或闪烁。
5. 手势划出食材边缘时，酱料从顶面连续过渡到侧面，并出现长度随流量变化的溢出效果。
6. 9 种材料的厚度、横向尺寸、纵向尺寸和贴合量都可在手机上实时修改；刷新后仍保留，复制 JSON 可复现相同外观。
7. 64 条最坏酱料轨迹、20 层汉堡和 390 × 844 视口下保持可交互，控制台无错误，完整自动化测试通过。
8. 更新仍发布到现有 GitHub Pages 链接，用户不需要安装新应用或更换测试地址。
