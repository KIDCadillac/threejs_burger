# 汉堡小游戏 Gauntlet 完成方案

更新日期：2026-08-01

## 为什么采用这套方法

参考项目 `achimala/TheLongSilence` 的公开技能本身是 BlenderMCP 硬表面飞船建模流程，并不能直接替代网页汉堡游戏开发。本项目只迁移它真正有价值的方法：把目标拆成可玩的纵向切片、在真实浏览器里反复渲染、用自动检查挡住技术回归、再用独立严格审查判断是否真正过关。

仓库内可交接技能：`.codex/skills/build-burger-game-gauntlet/`

## 当前总目标

先把经典牛肉堡做成一条完整、清楚、有手感的第一人称制作体验；寿司制作和旧 UI 编辑器整理在汉堡 P0 通过后再做。

## 当前切片：固定料理镜头 + 槽位级实体调料架

玩家可见结果：汉堡制作时镜头角度和玩家缩放固定；右侧三只真实调料瓶始终保留。玩家在某只瓶上直接左右滑，只切换该槽位；静止长按打开瓶形图标选择器，可明确指定这只瓶装什么；向上拖则拿起这只实体瓶，拖到汉堡上松手才确认落酱。底部全局胶囊不再出现。

验收条件：

1. 单指空白拖动不能旋转镜头，双指不能缩放镜头。
2. 三只实体瓶始终可见；底部不出现全局调料胶囊。
3. 水平位移达到 18 px 且横向占优时，只循环当前槽位；另外两槽保持原样。
4. 静止长按约 360 ms 打开三图标选择器；选择器锚定当前瓶并允许指定当前槽内容。
5. 向上位移达到 20 px 且纵向占优时，按 `slotId` 拿起这一只真实三维瓶子和右手；重复酱料也不能串槽。
6. 最终抬手位置必须命中汉堡；在别处松手、按 Esc、切后台、暂停或丢失指针都取消并归还原槽。
7. 文档级指针监听兜底，指针离开瓶身后移动与抬手仍能结束同一手势。
8. 自动测试、缓存版本链、浏览器控制台、移动窄屏布局和 `git diff --check` 全部通过。

本切片状态：已实现并完成本地自动化与 1280×900 浏览器视觉验收。全仓库 81/81 测试通过，缓存版本为 `20260802-gameplay30`；待提交推送后在 GitHub Pages 复验。

## 已完成切片：食材与手是一体动作

- 左侧食材使用镜像左手，右侧食材使用原始右手。
- 手的位置来自真实三维食材的屏幕投影，并贯穿 `start → move → end`。
- 放下后约 220 ms 退场，不遮挡成品。
- 经典订单已完整完成到 6/6 并通过结算。

## 后续纵向切片

### P0：经典汉堡最后一轮体验收口

- 同一移动窄屏完整重做 1/6 到 6/6，检查所有六步的手、食材、提示与结算。
- 调整“握住点”而不是单纯调整手图中心，确保小食材、面包和右侧三维调料瓶都读得出接触关系。
- 为错误食材补一段明确的拿起—拒绝—返回动作，不能只靠文字提示。
- 检查按铃结算、重做和撤销不会提前弹层或重播旧动画。

- 两侧主题不与中心主体叠加，返回方向也有完整动画。
- 旋转主体、标题、按钮和模式提示在同一节拍更新。

- 保留对齐、层级、方向键微调、文件导入导出；删除已经不再使用的轮子与车身专用入口。

## 每个切片的固定验收门

1. 写清楚一条玩家可见完成线。
2. 保存修改前同状态截图与复现路径。
3. 只实现这个切片，不顺手重做其它页面。
4. 跑 `.codex/skills/build-burger-game-gauntlet/scripts/run_repo_checks.ps1`。
5. 保存修改后 start / contact / release / settle 证据。
6. 最多启用一个独立审查者，按 `references/review-rubric.md` 给 PASS/FAIL。
7. 更新交接文档、提交、推送，并在 Pages 上用缓存参数复验。
