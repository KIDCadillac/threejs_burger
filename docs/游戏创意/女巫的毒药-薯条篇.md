# 《女巫的毒药：薯条篇》创意上下文

## 当前状态

- 阶段：本地双人网页原型已完成，等待玩法验收；抖音适配与上线工作尚未开始。
- 类型：双人、回合制、隐藏信息、心理博弈、轻量聚会游戏。
- 目标平台：优先考虑抖音小游戏。
- 当前优先级：先于《同舟不同心》探索。
- 产品形态：完全在屏幕中进行的虚拟双人游戏，不使用真实薯条作为游戏道具。
- 对局入口：同时提供在线快速匹配和邀请好友约战，不在二者之间二选一。

## 做菜主模式与首批汉堡配方

- 当前研发主线已经调整为“先把自由做菜框架做好”，汉堡是第一张可玩料理台；寿司是下一张地图，藏陷阱与双人对战作为建立在做菜框架上的后续模式。
- 开发期先参考麦当劳中国常见汉堡的名称、食材组合和成品层次，让配方容易理解和验收；正式商业版本不使用麦当劳名称、Logo、包装、角色或一比一产品美术，而改成原创品牌与原创菜单名。
- 2026-07-21 核对的麦当劳中国官方“汉堡和卷”菜单包含：巨无霸、汉堡包、麦辣鸡腿汉堡、板烧鸡腿堡、麦香鸡、麦香鱼、吉士汉堡包、双层吉士汉堡、不素之霸双层牛堡、双层深海鳕鱼堡、培根安格斯厚牛堡、芝士安格斯厚牛堡、培根蔬萃双层牛堡。
- 第一批优先做 4 个开发期参考配方：汉堡包、吉士汉堡包、双层吉士汉堡、巨无霸；先复用牛肉饼、芝士、酸黄瓜、洋葱、生菜、番茄酱、芥末酱和招牌风味酱，再扩展鸡肉、鱼排与培根。
- “汉堡包”参考结构：芝麻面包、100% 牛肉饼、酸黄瓜、洋葱粒、番茄酱；牛肉烹饪时以少量盐和胡椒调味。
- “巨无霸”参考食材：三层芝麻面包、双层牛肉饼、酸黄瓜、洋葱、生菜、芝士和招牌风味酱。游戏中的每一层仍可自由增减、换序和重复，不把参考配方做成唯一正确答案。
- 官方参考：[汉堡和卷菜单](https://www.mcdonalds.com.cn/index/food/menu/burger)、[汉堡包产品页](https://www.mcdonalds.com.cn/product/Hamburger)、[巨无霸产品说明](https://www.mcdonalds.com.cn/know_your_icon/big-mac-star-product)。

## 新玩法：订单式汉堡店

- 2026-07-23 新增想法：把自由搭建框架扩展成汉堡店接单玩法。玩家接到不同顾客订单后，根据订单要求选择面包、肉饼、芝士、蔬菜和酱料，并按顺序完成汉堡。
- 原料主要从料理台上方的吊架、出料槽或传送位置调取；玩家先选中目标原料，再让它落到当前备餐区，减少高层汉堡旁边堆满切换按钮的问题。
- 一张订单只突出当前需要处理的下一项材料，同时保留完整订单小票供玩家核对；完成后按材料准确度、层次顺序、酱料覆盖和用时结算。
- 后续可加入连续订单、限时高峰、错单返工、双人分工和观察后复刻等模式，但都沿用“选料、落料、拖动装盘、双指查看、撤销”的统一手感。
- 可以参考《老爹汉堡店》的“接单—制作—交付”节奏和容易理解的订单信息层级，但不复制其角色、店铺、美术、菜单名称、具体关卡和界面版式。

## 未来计划：原材料加工与生产过程

- 自由料理最终不只提供现成食材，还要允许玩家亲手生产和加工原材料；当前汉堡拼装台是这套系统的第一阶段。
- 面包坯首条完整流程为：准备原料 → 和面 → 发酵 → 分割/塑形 → 烘烤 → 冷却/切开 → 进入汉堡拼装台。玩家能看到面团体积、颜色、表皮和内部状态随工序变化，而不是用一张图片替换结果。
- 后续沿用相同框架扩展牛肉饼调味与煎烤、蔬菜清洗与切配、酱料混合，以及寿司的煮饭、调味、切料和卷制。
- 食材数据预留统一生命周期：`raw`（原料）→ `prepared`（已处理）→ `cooking`（加工中）→ `ready`（可装盘）→ `plated`（已装盘）。每个阶段可携带熟度、温度、含水量、形状、份量和品质等参数。
- 三维资产按“基础模型 + 工序状态 + 可交互部件”组织，同一块食材在加工过程中持续变化，避免每增加一道工序就重做整套料理逻辑。
- 当前阶段不立即制作烤箱、和面与发酵玩法；先把工作台槽位、触控、缩放、拼装、存档和镜头体验做稳。实现这些系统时必须保留食材实例标识与加工状态扩展位，避免未来接入生产流程时破坏已有汉堡存档。

## 已确认的汉堡操作规则

- 搭建模式使用固定角度：单指拖动不旋转镜头，双指可以自然缩放；“镜头复位”必须重新显示完整料理台。随着汉堡叠高，镜头只在装不下时自动后退，不擅自靠近或改变玩家选择的距离。
- 聚焦模式只看当前汉堡：可以自由旋转、缩放、选中某一层并删除；返回料理台后恢复搭建角度和搭建距离。
- 材料台固定为 10 个独立物理槽位：左侧 3 个面包格、后侧 4 个夹料格、右侧 3 个酱料格。支持的手机宽度中不得合并成 3 个总分类按钮；每格轻触循环当前格材料，长按只打开当前格的完整候选列表。
- 极窄屏幕（小于 360 CSS 像素）允许使用面包、夹料、酱料 3 个紧凑入口，但入口展开后仍要分别操作全部 10 个物理槽位。

## 跨模式统一操作标准

- 做菜、计时淘汰、关卡、找不同重排、双人复刻和后续陷阱玩法只改变目标、倒计时、胜负与对手信息，不改变玩家已经学会的操作。
- 全模式统一为：轻触槽位快速换下一种材料；长按同一槽位展开全部候选；拖动三维食材直接拿取与放置；双指缩放；撤销永远位于底部工具栏。
- 主要动作在松手时确认，滑出目标或取消手势不会误操作；成功切换、展开和选择都用同一套轻量弹跳、视觉高亮与可用时的短触觉反馈。
- 材料切换入口贴着料理台外沿，保留不少于 44×44 CSS 像素的命中区，但可见按钮必须小而清楚，不遮挡汉堡与三维材料。
- 长按候选胶囊展开时，其他槽位降低强调；轻触选择或再次轻触槽位后立即收起，不保留挡住料理区的悬浮菜单。
- 教程只解释玩家当前能做的一件事，使用“拿起、放下、换材料、撤销”等儿童能直接理解的词；不依赖颜色区分状态。
- 设计原则参考 Apple 游戏输入、Xbox 无障碍输入与导航规范，以及触屏烹饪游戏的直接操作经验；只借鉴信息层级和交互原则，不复制第三方图标、角色、资产或具体版式。

## 已核实的参考玩法

1. 双方各自在同一组食物中秘密指定一份作为自己的“毒药”，不能让对手知道。
2. 双方轮流选择一份食物。
3. 玩家若选中对方秘密指定的“毒药”，立即中毒并落败，对方获胜。
4. 食物不断减少后，安全范围越来越小，猜测、表情误导和揭晓反应构成主要节目效果。
5. 网络上存在水果、炸串、薯条、盲盒及带惩罚的桌游扩展等变体；这些是同一基础机制的不同包装，并非本项目已经确定的规则。

## 方向纠正

- 本项目的核心不是“双人共同操纵一个角色抓取食物”。
- 本项目的核心不是按颜色争抢各自食物。
- 女巫题材目前只作为名称与气氛参考，不应把玩法改成魔法厨房、角色抓取或动作闯关。
- 正确的核心循环是：秘密藏毒 → 轮流试探 → 选项减少 → 毒药揭晓 → 胜负与安全惩罚结算。
- 参考视频中的角色能力、道具牌、食物牌和惩罚层只能用于分析扩展空间，不能直接复制其名称、卡面、数值或完整规则组合。

## 节目效果来源

- 玩家知道自己的毒药位置，却不知道对方的毒药位置。
- 每次选食物前都能观察对方的表情、停顿和语言误导。
- 剩余食物越少，风险越集中。
- 选中瞬间立刻揭晓，形成清晰的惊吓、庆幸或反转节点。
- 单局短、规则简单，适合连续重赛和直播互动。

## 已实现的表演层

- 部署时，目标零食和下料动画只在本人设备显示；对手仍能看到角色“鬼鬼祟祟、偷偷搅拌、抱住配方”等公开动作。
- 回合中双方都能点击“装镇定、偷笑、指错方向、催他快吃”；使用固定动作而不是自由聊天，降低审核与辱骂风险。
- 当前玩家先公开瞄准一件零食，观察对手动作后可改选一次，再确认吃下。
- 命中后先播放强装镇定到表情崩坏的三段演出，再回放当前零食当初被下料的过程；回放不会泄漏其他陷阱。
- 首版混合零食包含薯条、汉堡、甜甜圈、曲奇、三明治和果冻，已经换成偏真实的卡通食物素材；零食外观只改变演出，不改变胜率。

## 原创特色：赛前调制整蛊零食

每回合开始时，双方不是只点击一个“炸弹”，而是在同一盘公共零食里秘密制作一件属于自己的整蛊零食：

1. 从公共零食盘中秘密选择一件作为目标。
2. 切开或打开食物，把辣椒酱、芥末、酸味汁、黏酱等虚拟调味料拖到食物内部；每次可加 1～4 份，允许重复和混搭。
3. 确认后播放私人下料；对手只能看见角色动作，不能看见零食位置、种类和酱料。
4. 对局中若对手吃到这件零食，镜头拉近对手的游戏角色，播放与配方对应的夸张表情，再回放该件零食的下料过程。

### 表情组合示例

- 辣椒酱：脸迅速变红、冒汗、喷出卡通火苗。
- 芥末：鼻子一酸、眼泪喷涌、头发竖起。
- 酸味汁：五官收紧、脸颊凹陷、身体短暂抖动。
- 黏酱：嘴被黏住，只能发出含糊声音和挣脱动作。
- 辣椒酱 + 芥末：先强忍镇定，再突然红脸流泪，形成二段反应。
- 酸味汁 + 黏酱：五官缩紧后嘴巴拉长，形成组合表情。

### 平衡原则

- 基础模式中，所有配方命中后都只决定该回合胜负，不改变命中概率。
- 调味料主要改变揭晓演出、表情、音效和收藏记录，避免付费调味料形成战力优势。
- 首版只做少量辨识度很高的调味料和组合，不做复杂烹饪数值。
- 所有反应均发生在虚拟角色身上，不鼓励玩家在线下模仿极辣、芥末或混合刺激物挑战。

### 长线价值

- 玩家可收集新酱料瓶、瓶身皮肤、装盘方式和表情演出。
- 结算页记录“本局配方”，方便截图、录屏和分享。
- 稀有内容以视觉演出和个性化为主，可作为广告奖励或装扮商业化内容。

## 联机与邀请方向

### 首页入口

1. `快速匹配`：进入真人匹配队列，成功后直接进入双方准备阶段。
2. `邀请好友`：立即创建双人房间并调用抖音好友邀请面板；好友点击私信卡片后直接进入该房间。
3. `输入房间码`：作为链接、私信卡片或拉起参数失效时的低优先级兜底入口。

### 参考产品中可学习的部分

- 学习《狙击外星人》把随机对战和好友房间放在同一个双人玩法入口下的结构。
- 学习“创建房间 → 邀请约战 → 好友点击分享或输入房间号加入”的短链路。
- 不复制它的按钮造型、页面布局、名称、角色、美术或射击玩法。

### 抖音平台能力与自有服务分工

- 抖音平台：用户登录、好友邀请面板、私信游戏卡片、分享拉起参数和后续录屏分享。
- 游戏服务端：真人匹配队列、房间创建与回收、回合状态、毒药位置、掉线重连和胜负判定。
- 对局通过安全 WebSocket 连接实时同步；隐藏信息只由服务端向有权看到的一方下发。
- 好友邀请卡片携带房间标识；若使用动态组队卡片，房间开始或失效后同步更新卡片状态。

### 默认体验决策

- 快速匹配默认匹配真人，不把机器人伪装成真人。
- 冷启动人数不足时，明确提供“继续等待”或“与练习对手开局”，不暗中替换。
- 好友进入后省略复杂房主设置，双方加载完成即开始藏毒。
- 房间码采用短数字码并设置有效期，避免永久占用和误入旧房间。

## 安全边界

- 小游戏内的惩罚优先采用夸张表情、临时状态、积分变化或无伤害互动。
- 不把打耳光、推搡、踢人、强迫进食、极辣食物或饮酒设计成推荐玩法。
- 若保留线下食物辅助模式，需要提示过敏、噎食、辛辣刺激和未成年人风险。

## 验收后的下一阶段

1. 根据双人试玩数据调整薯条数量、单局时长和表情演出节奏；首版暂不加入角色战力或道具牌。
2. 将本地邀请适配器替换为抖音小游戏登录、好友邀请/私信卡片和拉起参数能力。
3. 把单进程内存房间迁移到可横向扩展的正式房间服务，补充鉴权、监控、限流和数据持久化。
4. 准备原创美术、音效、隐私与未成年人内容说明，再进入平台审核和小流量测试。
