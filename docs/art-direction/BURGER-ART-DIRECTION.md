## 从小黑盒分享链接学到的工作方法

本轮能直接确认的是分享卡片元数据与缩略图：作者用 Codex、Imagegen、透明 PNG 和 Pull Request 组织游戏迭代。文章正文页面未能直接读取，因此这里只采用能从分享信息和可见缩略图确认的方法，不臆测文章中的具体实现。

可执行的学习点不是“让 AI 一次画完整页”，而是：

1. 把 AI 生成拆成可替换的素材工序。
2. 给每张素材明确的槽位、尺寸、背景和透明度要求。
3. 固定调色板、描边粗细、光影强度和禁止项。
4. 生成后立即放回真实页面测试，不能只看单图。
5. 用 Git 分支和对比图记录每次改动，避免审美方向反复漂移。

## 色板

- 奶油黄：`#ffe7a1` / `#f8d36d`
- 番茄红：`#e64a35`
- 芥末黄：`#f2ad2e`
- 蓝绿色：`#77bcc5`
- 深棕描边：`#3b251c`
- 暖白：`#fff2cc`

允许轻微明暗差，禁止把整体改成写实金属、霓虹塑料或软陶 3D。

## 造型与描边

- 主轮廓使用深棕色，视觉粗细保持一致。
- 车身和 UI 形状要规整但不要机械写实。
- 食物层次必须一眼可辨：面包、生菜、番茄、芝士、肉饼分别有独立色块。
- 阴影只用于分层，不做摄影级环境光、镜头光晕和浅景深。
- 禁止品牌 Logo；可以使用通用汉堡图形和中文店名。

## AI 素材合同

每次生成必须包含：

- 权威参考图。
- 素材实际使用尺寸与裁切方式。
- 只画一个明确对象或一个明确场景槽位。
- 平涂、粗深棕描边、有限色板、低渐变。
- 无文字、无品牌 Logo、无水印；文字由 HTML/CSS 负责。
- 无摄影质感、无塑料高光、无黏土 3D、无景深。

当前允许的 AI 槽位：

- 出餐窗口中的厨师递汉堡插画。
- 菜单翻牌中的汉堡、薯条、饮料和未来套餐图。

整车轮廓、信息层级、镜头和交互必须由现有页面结构控制。

## 餐车镜头语言

1. 初始只显示场景背景。
2. 整台餐车从右侧进入卡片，车轮同时滚动。
3. 车停稳，车身轻微回弹。
4. 卷帘打开，菜单开始翻转。
5. 镜头向出餐窗口推进，最终保留招牌、菜单和汉堡。

最终近景不能出现大轮胎挡脸、黑色圆形遮挡、按钮盖住汉堡或无意义空白。

## 验收方法

每轮至少保留三张证据：

- 原风格参考。
- 整车进场状态。
- 最终出餐近景。

把三张图放在同一个比较画布中，逐项检查色板、描边、构图、裁切、菜单可读性、汉堡主体和交互控件。只有没有未解决的 P0、P1、P2 问题时，`design-qa.md` 才能标记 `passed`。
